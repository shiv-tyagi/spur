## [0.16.0](https://github.com/shiv-tyagi/spur/compare/v0.15.0...v0.16.0) (2026-10-21)


###   BREAKING CHANGES

* **spur-cli:** honor ExcNodeList in scontrol update and fail on unknown keys ([#1089](https://github.com/shiv-tyagi/spur/issues/1089))
* **spurctld:** a cluster that preempted before stops preempting until preempt_type is set explicitly, and eligibility now requires a QOS allow-list entry. See docs/deployment/upgrading.rst.
* **spur-cli:** exit non-zero when scancel refuses a cancel ([#1014](https://github.com/shiv-tyagi/spur/issues/1014))
* **spurctld:** add [auth] private_data for job and usage visibility ([#1013](https://github.com/shiv-tyagi/spur/issues/1013))
* **spurctld:** add idle-fill scheduling ([#881](https://github.com/shiv-tyagi/spur/issues/881))
* **spur-core:** use Slurm's exact reserved step-id sentinels ([#909](https://github.com/shiv-tyagi/spur/issues/909))
* **spurd:** supervise every job with spurstepd by default ([#754](https://github.com/shiv-tyagi/spur/issues/754))
* **core:** two-field colon time values now mean minutes:seconds rather than hours:minutes, so they resolve to 1/60th of their previous duration. This affects `-t`/`--time` on sbatch, srun and salloc, and partition `MaxTime`/`DefaultTime`. Job scripts and site configs relying on the old reading should switch to the explicit `HH:MM:SS` form, which was and remains unambiguous. Bare `days-hours` now produces a real limit where it previously produced an unlimited job.
* **spurd:** stop injecting torch rendezvous env vars, match Slurm ([#793](https://github.com/shiv-tyagi/spur/issues/793))
* **spurctld:** store job ids as 64-bit in the accounting database ([#753](https://github.com/shiv-tyagi/spur/issues/753))
* **spurctld:** enforce reservation management privileges server-side ([#726](https://github.com/shiv-tyagi/spur/issues/726))
* **spurctld:** enforce QOS and association submit-time limits ([#670](https://github.com/shiv-tyagi/spur/issues/670))
* **spur-cli:** non-privileged users can no longer manage reservations via the CLI; scripts relying on the old permissive behavior will fail.
* **spurd:** drop --comm-address alias and SPUR_COMM_ADDRESS ([#562](https://github.com/shiv-tyagi/spur/issues/562))
